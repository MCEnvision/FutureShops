# phase 002 security review

## Scope and trust boundaries

The review covers `compat.pixelmon`, its common setup registration, the public provider capability gate, the exact optional class boundary, and the built 2.3.0 jar. Pixelmon classes and account values are external dependency input. Player UUIDs, provider configuration, account identities, balances, and reflection results are treated as untrusted. The server coordinator remains the only mutation boundary.

## Findings

No high, medium, or low severity exploitable finding was identified in the changed code.

The adapter does not invoke Pixelmon mutation methods. It validates the account identity against the requested player, converts `BigDecimal` balances with exact scale and range checks, bounds all diagnostics through the provider result contract, and maps missing, thrown, fractional, and invalid values to typed non confirmed results. The coordinator checks capability declarations before journal, custody, inventory, claims, analytics, or success event effects.

Registration checks the loaded mod id and exact version `9.4.0` before adding the provider. No Pixelmon, Bukkit, Spigot, Vault, or bridge classes are imported or declared as dependencies. Runtime class loading is isolated and catches reflection and linkage failures without exposing exception content in diagnostics. The same jar starts in standard server and client smoke tests without Pixelmon.

No generic Vault or legacy bridge production mutation claim is made.
