## Archive and API inspection

The exact jar contains 58545 entries and 7927 class files. `jar tf` confirmed `BankAccount`, `BankAccountManager`, `BankAccountProxy`, `PlayerPartyStorage`, `StorageProxy`, `StorageSaveAdapter`, and `StorageSaveScheduler`. The economy package contains 10 entries. The archive contains no Pixelmon Java sources, Javadoc archive, or Pixelmon Maven descriptor. The three Maven POM pairs present are for bundled third party libraries only. `javap -public` and `javap -c -p` were run against the exact jar, without modifying it.

The reviewed declarations are:

* `BankAccount` provides UUID identity, `BigDecimal` balance and precheck, and boolean `add` and `take` mutations.
* `BankAccountManager` and `BankAccountProxy` provide synchronous and asynchronous account lookup.
* `PlayerPartyStorage` implements `BankAccount` and stores the balance in the `pokeDollars` field.
* `StorageProxy`, `StorageSaveAdapter`, and `StorageSaveScheduler` expose storage lookup and save boundaries.
* `EconomyEvent.PreTransaction` and `EconomyEvent.SetBalance` are cancellable. `EconomyEvent.PostTransaction` reports old and new balances.

The decompiled `PlayerPartyStorage` bytecode shows `writeToNBT` writes `pokeDollars` as the `pixelDollars` string, while `setBalance`, `add`, and `take` update the balance, call `updatePlayer`, and mark the storage dirty with `setNeedsSaving`. The native methods accept no FutureShops request UUID, receipt key, or retry token. The events expose balance values and transaction type but no operation identity or receipt lookup. This observation is an input to the later capability and mixin tasks, not a mutation authorization.
