## Preliminary Pixelmon API observations

The official Pixelmon 9.4.0 API reference identifies the economy package as `Pixelmon 9.4.0-PIPE30856 API`. The documented `BankAccount` interface exposes a UUID identifier, `BigDecimal` balance reads, balance checks, and `BigDecimal` `add` and `take` mutations. `BankAccountManager` and `BankAccountProxy` expose asynchronous and immediate account lookup by UUID, and `PixelmonInitEvent` exposes the account manager during Pixelmon initialization. The documented `EconomyEvent.PreTransaction` is cancellable before an account mutation and supplies the transaction type, prior balance, and requested change. `EconomyEvent.PostTransaction` is emitted after the mutation and supplies old and new balances.

Running `javap -public` against the acquired `Pixelmon-1.21.1-9.4.0-universal.jar` confirmed the same public declarations in the exact runtime bytes, including `BankAccount`, `BankAccountManager`, `BankAccountProxy`, `PixelmonInitEvent`, `EconomyEvent.PreTransaction`, `EconomyEvent.PostTransaction`, and `EconomyEvent.TransactionType`.

The additional `javap -c -p` inspection shows that `BankAccountManager.getBankAccountNow(UUID)` joins the asynchronous future, `BankAccountProxy` forwards directly to a static manager without an absent manager guard, and the numeric overloads convert to `BigDecimal` before calling the abstract operations. The only account mutations are boolean `add(BigDecimal)` and `take(BigDecimal)` calls. No public Pixelmon economy declaration accepts a request UUID, operation context, or receipt lookup key. This means the exact API can support balance lookup and preflight cancellation, but it cannot by itself prove nonblocking gameplay use, crash safe idempotency, or durable outcome recovery.

These pages establish a possible query and preflight integration surface, but they do not prove the phase contract. The documented mutation methods return only a boolean and accept no FutureShops request UUID or durable receipt lookup. The documented events likewise expose balance values and transaction type, not a stable operation identity. The exact runtime bytes and public declarations are now verified, but implementation behavior and any bridge supplied idempotency or outcome lookup remain unverified. The missing development bundle keeps `EXT-001` incomplete and the missing mutation and recovery proof keeps `EXT-003` blocked. Sources: [BankAccount](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/economy/BankAccount.html), [BankAccountManager](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/economy/BankAccountManager.html), [BankAccountProxy](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/economy/BankAccountProxy.html), [PixelmonInitEvent](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/events/init/PixelmonInitEvent.html), [EconomyEvent.PreTransaction](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/economy/EconomyEvent.PreTransaction.html), and [EconomyEvent.PostTransaction](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/economy/EconomyEvent.PostTransaction.html).
