## Transaction boundary review

The bridge `VaultBankAccount` implementation delegates balance and mutation calls through Vault. Its balance path converts a Vault `double` through `Math.floor`. Its `take` and `add` paths expose only boolean or void results. Targeted inspection of `FinalEconomyAPI`, `IFinalEconomy`, `VaultEconomy`, `FEBankAccount`, and `VaultBankAccount` found no FutureShops request UUID, durable receipt, receipt lookup, idempotent retry, or provider owned transaction journal.

| Required capability | Result |
| --- | --- |
| balance query | present, but conversion is lossy because the bridge floors a `double` |
| precheck | present through Vault funds check |
| withdraw | boolean result only, no durable receipt |
| deposit | void bridge path, no durable receipt |
| receipt lookup | absent |
| idempotent retry | absent |

A successful boolean or Vault response cannot prove whether the external effect happened after a crash before local persistence. A local FutureShops receipt cannot retroactively make the external operation idempotent. The bridge therefore does not satisfy the strict mutation contract and must remain refused.

## Terms and security disposition

The public repositories for PixelmonEconomyBridge, FinalEconomy, and EverNifeCore expose no recognized GitHub license metadata and no root license file. This leaves license provenance unresolved for the separately installed candidate. The artifacts remain outside the repository and are not redistributed. No source was copied into FutureShops. The bridge archive passed integrity checks and no credentials or private player data were read.

The bridge is a Bukkit stack with a different classloader and lifecycle boundary. FutureShops standard NeoForge startup must continue to work with none of Bukkit, Vault, PixelmonEconomyBridge, EverNifeCore, or FinalEconomy present. Any later proof backend must be separate first party test code and must never be confused with this production candidate.
