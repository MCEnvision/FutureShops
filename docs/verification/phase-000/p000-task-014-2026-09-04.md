## Frozen command and module contract

The only canonical commands are:

```text
/futureshops debug on <module>
/futureshops debug off
/futureshops debug status
```

The command uses the existing FutureShops operator permission boundary. The accepted modules are `all`, `provider`, `lifecycle`, `transaction`, `receipt`, `recovery`, `pixelmon`, `vault`, `network`, and `surface`. Invalid modules and unauthorized callers receive a typed rejection and one bounded diagnostic.

Debug is disabled by default, server authoritative, non persistent, and disabled on restart. A client cannot enable it. Toggling a module cannot change provider selection, readiness, transaction outcomes, safety rules, journal state, custody, claims, or recovery decisions.

Amounts are minor units and appear only when needed to reproduce an issue. Retained actor identifiers are stable pseudonyms or request identities. Actionable stack traces are sanitized before retention.

Diagnostics are event based, bounded, and rate limited. They do not log every tick, screen refresh, balance poll, or retry without a state change. A client record is never authoritative and never authorizes a mutation.
