# Phase 000 task 007 provider registry

## Scope and result

This packet records `P000-TASK-007`. The NeoForge provider registry validates identifiers and factories, reserves `internal` and `vault`, rejects duplicates and late registration, snapshots registrations in deterministic order, validates provider identity and compatibility metadata, and freezes before provider selection. Capability and readiness failures become explicit resolution states. Registration order cannot select a different provider or hide a conflict.

## Registry contract

`EconomyProviderRegistry` stores registrations in a sorted map guarded by one lock. Generic registration rejects invalid identifiers, null factories, compatibility versions below one, reserved identifiers, duplicate identifiers, and registration after freeze. The dedicated `registerVault` method is the only path for the reserved `vault` identifier and still validates its factory and compatibility version.

`freeze` is idempotent and prevents later registration. `snapshot` returns an unmodifiable sorted copy. `resolve` returns `UNRESOLVED` until freeze, `MISSING` for an absent identifier, `INCOMPATIBLE` for a registration or provider metadata version mismatch, `FAILED` for factory or identity and metadata exceptions, the provider's nonready lifecycle when readiness is not ready, and `READY` only after provider id, compatibility version, currency, capabilities, and readiness all validate.

The registry validates the provider returned by a factory against the registered identifier and API compatibility version. It requires nonnull currency, capabilities, and readiness values. It does not infer mutation support from a provider name. The capability descriptor remains independent and is consumed later by the transaction coordinator.
