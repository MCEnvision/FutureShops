## Runtime and compatibility observations

The authorized profile loaded FutureShops `2.3.0`, Pixelmon `9.4.0`, GeckoLib `4.8.4`, NeoForge `21.1.248`, Vault `1.7.3`, FinalEconomy `1.0.9`, EverNifeCore `2.0.4.4`, and PixelmonEconomyBridge `1.1.6`. The log recorded `FutureShops common setup complete`, plugin loading and enabling, `Integrating Pixelmon to Bukkit`, `FinalEconomy was found`, `FutureShops server starting`, and a normal `Done` line. This confirms that the components can run as regular unmodified external mods and plugins in the disposable hybrid profile.

The bridge source module targets Pixelmon `9.3.0` and NeoForge `21.1.174`, while the runtime profile uses Pixelmon `9.4.0` and NeoForge `21.1.248`. The bridge artifact loaded successfully, but loadability is not proof of exact transaction compatibility. FinalEconomy's source targets older Spigot and Java boundaries and stores balances as `double`. EverNifeCore and FinalEconomy repositories expose no recognized license metadata or root license file. These facts keep the stack's terms and production compatibility classifications explicit.

## Strict economy boundary

The stack offers balance lookup and funds checks through Vault and the bridge. Its mutation paths return boolean, void, or ordinary Vault response values. No component in the reviewed stack persists a FutureShops request UUID with the balance effect, exposes durable receipt lookup, or deduplicates retries. The bridge also floors `double` values, so exact integer minor unit conversion is not proven.

| Required property | Result |
| --- | --- |
| regular external runtime startup | verified in the disposable profile |
| exact target versions | Pixelmon and NeoForge exact, bridge and economy source pins not exact |
| balance query and precheck | available through the bridge |
| exact integer conversion | not proven, bridge floors `double` |
| one transaction for balance effect and receipt | absent |
| durable request lookup | absent |
| idempotent retry | absent |
| license provenance for all third party artifacts | unresolved for EverNifeCore and FinalEconomy |

The unmodified stack therefore remains ineligible for `vault` mutation registration. FutureShops keeps the standard NeoForge path free of Bukkit and Vault classes. A separate first party test registrant and durable backend proof may be built in Phase 002, but it must remain outside the published FutureShops jar and cannot certify this legacy production bridge.
