# Phase 000 task 006 public economy API contract

## Scope and result

This packet records `P000-TASK-006`. The provider neutral API is frozen at compatibility version `1`. It carries stable provider identifiers, immutable currency metadata, independent capabilities, lifecycle readiness, exact integer values, request UUIDs, typed outcomes, durable receipt records, lookup, retry, threading expectations, and exception containment. Public API types do not depend on internal economy implementations, Pixelmon, Bukkit, Vault, bridge, or hybrid classes.

## Stable surface

`EconomyApi.COMPATIBILITY_VERSION` is `1`. The reserved identifiers are `internal` and `vault`. Provider identifiers must be lowercase, begin with a letter, contain only lowercase letters, digits, or underscore, and be 2 through 64 characters. Reserved identifiers cannot be registered by a third party factory.

`EconomyCapability` is the independent set `BALANCE_QUERY`, `PRECHECK`, `WITHDRAW`, `DEPOSIT`, `RECEIPT_LOOKUP`, and `IDEMPOTENT_RETRY`. A provider capability does not imply any other capability. Each mutation surface requires the complete capability set before the transaction coordinator can admit it.

`EconomyProvider` exposes `providerId`, `compatibilityVersion`, `currency`, `capabilities`, `readiness`, `balance`, `precheck`, `withdraw`, `deposit`, `lookup`, and `retry`. Provider implementations run on the logical server and must not block that thread on unbounded work. A local request UUID alone is explicitly insufficient to make an external boolean call idempotent.

`MutationKind` distinguishes `WITHDRAW`, `DEPOSIT`, `TRANSFER_DEBIT`, `TRANSFER_CREDIT`, `FEE`, `REFUND`, and `COMPENSATION`. `MutationRequest` carries the actor, request UUID, semantic kind, and checked minor unit amount. `MutationReceipt` binds the same request UUID, operation kind, amount, provider receipt identifier, and optional resulting balance. `ProviderResult` and `ProviderResultStatus` preserve confirmed, rejected, unavailable, recovery required, ambiguous, and failed outcomes without converting uncertainty to success. `ProviderReadiness` and `EconomyLifecycleSnapshot` expose lifecycle and diagnostic state.

## Contract invariants

* Values are signed integer minor units. Conversions reject fractional, nonfinite, overflowing, or lossy external values.
* Request identities are stable and must match the receipt returned by a provider.
* `lookup` is the only authoritative way to resolve an external request after an interrupted operation.
* `retry` is callable only when the provider proves deduplication by the same request UUID.
* Missing, malformed, ambiguous, or throwing provider responses become typed failure or recovery states.
* Lifecycle failure disables monetary admission and never falls back to `internal`.
* The coordinator checks capabilities before appending intent or creating custody. A false capability leaves the journal, custody, inventory, claims, analytics, events, and external provider unchanged.
* Public contracts remain free of Pixelmon, Bukkit, Vault, bridge, and internal implementation types.

The internal provider is the only implementation that currently exposes all six capabilities. The Pixelmon provider exposes balance query and precheck only. The reviewed Vault bridge is not registered because it lacks receipt and retry guarantees. These differences are represented as immutable capability data, not inferred from provider names or load order.
