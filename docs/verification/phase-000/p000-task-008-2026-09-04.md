# Phase 000 task 008 restart only provider selection

## Scope and result

This packet records `P000-TASK-008`. Server provider selection resolves once at startup, defaults an absent or blank configuration to `internal`, keeps active and staged values separately, reports when a restart is required, and never falls back from an unavailable external provider to the internal wallet. Reload stages a value only. Restart is the only activation boundary.

## Selection behavior

`ProviderSelectionManager.resolveAtStartup` normalizes an absent or blank value to `internal`, sets both active and staged identifiers, marks the selection resolved, and validates the identifier. `stageReload` changes only the staged identifier and its diagnostic. `snapshot` reports active id, staged id, resolved state, and restart required when the two differ.

`BalanceManager.initialize` freezes the provider registry before resolving the configured id. It creates the journal, custody, claims, receipt audit, escrow, settlement, and internal receipt stores before provider resolution. The internal provider uses the durable internal implementation. Any other selected id must resolve through the frozen registry. A ready provider receives a coordinator. A missing, incompatible, failed, or nonready resolution produces `UnavailableEconomyProvider` and a nonready lifecycle. No branch replaces it with `internal`.

External selection remains selected even when the provider is absent or capability deficient. Queries and mutation surfaces receive typed lifecycle or capability results. Reload cannot mutate the active provider, and a failed reload does not change the active selection. Restart resolves the staged configuration and constructs the new provider exactly once.
