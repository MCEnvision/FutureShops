This file does not broaden issue 22 into a rendering redesign, does not assign work to another support line, and does not permit publication. `EXT-001` is mandatory for actual phase and requirement closure. If it remains unavailable after all internal work is integrated, this phase records an internal-integration gate rather than a completed exit. That gate permits the independent work in `CORE-PHASE-002` to begin while issue 22, `CORE-REQ-003`, this phase's external acceptance gate, and the final endpoint remain explicitly blocked.

## Architecture and Implementation Boundaries

The correction belongs entirely to the NeoForge client presentation package `com.enviouse.futureshopsp.client.screen`. The intended dependency direction is concrete FutureShops screens to one shared shop-screen background policy to the vanilla `Screen` API. No common initializer or dedicated-server path may load the new client class. The marker or another deterministic inventory contract must make omission of a newly added concrete shop screen detectable.

The policy may suppress only the vanilla background pass responsible for issue 22. Existing screen render methods remain responsible for their intentional custom full-screen dim surface, panels, cards, controls, item rendering, text, hover states, and tooltips. Vanilla widget dispatch, tooltip layering, focus, keyboard and mouse input, narration, pause behavior, resize and reinitialization, parent-screen return, and ordinary close behavior remain intact. A global graphics option, blur strength, shader, renderer, resource pack, mixin, or unrelated Minecraft screen behavior must not be changed.

This phase has no authoritative state mutation, networking, configuration schema, persistence, command, permission, economy, escrow, or market change. A client screen may continue to display server-supplied state and send its existing requests, but issue 22 does not authorize protocol changes or any movement of authority to the client. The fix must remain harmless when no world is loaded, when the client is paused, during resize, and while screens are nested through parent references.

Version authority remains the NeoForge branch's canonical build property and generated mod metadata. The final JAR must resolve `2.2.1` consistently. Minecraft `1.21.1`, NeoForge `21.1.233`, ModDevGradle `2.0.141`, Java 21, mappings, GeckoLib, identifiers, resource namespace, network protocol, and persisted schemas remain unchanged unless the master is explicitly revised. The Forge line must have no diff from this phase.

The existing candidate is evidence, not authority. If its empty final override is broader than necessary, a screen relies on vanilla background behavior, its test can pass while a concrete shop screen escapes coverage, or the parent render order differs from the hypothesis, implementation must be corrected within this boundary and all evidence rerun. Do not preserve a candidate detail solely because it previously built.
